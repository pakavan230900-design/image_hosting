# Сервер зображень

Веб-сервіс для завантаження та зберігання зображень. Користувач завантажує
файл — сервіс повертає пряме посилання на нього, яке можна використовувати
де завгодно.

## Технології

- **Python 3.12** (тільки стандартна бібліотека `http.server` + `Pillow` для перевірки зображень)
- **Nginx** — роздача завантажених зображень і проксування інших запитів
- **Docker / Docker Compose** — контейнеризація

## Структура проекту

```
image-hosting/
├── app.py                # Python-бекенд: маршрути, валідація, логування
├── requirements.txt      # залежності Python (Pillow)
├── Dockerfile             # multi-stage build для бекенду
├── docker-compose.yml    # опис сервісів app + nginx
├── nginx.conf             # конфігурація Nginx
├── .dockerignore
├── static/
│   ├── index.html         # головна сторінка з формою завантаження
│   └── style.css
├── images/                # сюди зберігаються завантажені зображення
├── logs/                  # тут лежить app.log
└── README.md
```

## Вимоги до оточення

- Docker Desktop (включає Docker Compose)
- Більше нічого встановлювати не потрібно — Python і всі залежності
  збираються всередині контейнера.

## Запуск

Одна команда з кореня проекту:

```bash
docker compose up --build
```

Після запуску:

- Бекенд напряму: http://localhost:8000
- Через Nginx (основний спосіб для користувача): http://localhost:8080

## Зупинка

```bash
docker compose down
```

Дані (завантажені зображення та логи) не видаляються — вони зберігаються
у папках `images/` та `logs/` на диску, оскільки підключені як bind mount,
а не як анонімний том, який знищується разом з контейнером.

## Маршрути

| Маршрут | Метод | Опис |
|---|---|---|
| `/` | GET | Головна сторінка з формою завантаження зображення |
| `/upload` | POST | Завантаження зображення (`multipart/form-data`, поле `file`) |
| `/images/` | GET | Каталог усіх завантажених зображень |
| `/images/<ім'я_файлу>` | GET | Пряме посилання на конкретне зображення (роздає Nginx) |
| `/static/<файл>` | GET | Статичні файли (CSS) |

### Приклад завантаження через curl

```bash
curl -X POST -F "file=@photo.jpg" http://localhost:8080/upload
```

Успішна відповідь:

```json
{
  "message": "Файл успішно завантажено",
  "filename": "d55715b2bb3c480b8af53a2cdf337ca8.jpg",
  "url": "/images/d55715b2bb3c480b8af53a2cdf337ca8.jpg"
}
```

## Обмеження

- Формати: `.jpg`, `.jpeg`, `.png`, `.gif`.
- Максимальний розмір файлу: 5 МБ.
- Перевіряється не тільки розширення файлу, а й реальний вміст (через
  Pillow) — файл із підробленим розширенням буде відхилений.

## Логування

Усі дії (успішні завантаження та помилки) записуються у `logs/app.log`
у форматі:

```
[2026-01-24 14:00:00] Дія: Успіх: зображення img1.jpg завантажено.
[2026-01-24 14:01:00] Дія: Помилка: непідтримуваний формат файлу (user_file.txt).
```

## Безпека

- Завантажені файли перевіряються за розширенням, розміром і реальним
  вмістом (Pillow), перш ніж потрапити на диск.
- Захист від path traversal при читанні файлів (`/images/`, `/static/`).
- Доступ до зображень можливий тільки через маршрут `/images/<ім'я>` —
  жодних обхідних шляхів.

## Архітектура

Nginx (порт 8080 назовні, 80 всередині контейнера) роздає файли з
`/images/` напряму з диска та проксує решту запитів (`/`, `/upload`,
`/static/...`) на Python-бекенд (`app:8000`) всередині мережі Docker
Compose.
